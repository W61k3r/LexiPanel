Measure again
      

        Uses the server's only slot for the whole run: agent requests queue behind it, and its
        prompt cache is replaced by the test text. Depths are walked upward reusing the cached
        prefix, so the run costs one cold prefill of the deepest point (about 18 minutes to
        240k on the 7900 XTX), plus a few seconds per sample. The run pauses before a request
        at the pause temperature, and cancels the request in flight if the junction stays at or
        above the abort limit.

Host RAM budget

    

      VRAM is not the only ceiling. When the card runs near full, amdgpu evicts model
      weights into GTT — host RAM pinned by the driver, which shows up in
      neither ps RSS nor the cgroup. GTT ceiling + prompt cache + process
      overhead has to fit in physical RAM. It did not between Sep 4 and Sep 8,
      and nothing in this panel was modelling it.

Autopilot · optimize my workload

    

      Say what matters and the hard limits; the autopilot measures instead of guessing, on this
      instance, in stages: baseline (full suite, speed, decode at your depth) →
      model files → one lever at a time (backend, speculative type, KV type,
      projector placement, batch, draft tuning, cache reuse; anything that cannot fit at your
      context is skipped, never launched) → second pass (near misses retried on the
      final combination) → depth curves on the top configurations → full quality
      suite on the finalists. Every result records the build, driver, kernel, power cap and
      model checksum it was measured on. Typically 5–8 hours at quick budget; the server
      restarts many times. Your saved settings are restored at the end. Nothing is applied until you
      press Apply, and Apply can be rolled back.

Optimize 

    

      Benchmarks the selected instance on agentic coding work and searches for faster, more
      accurate and more consistent settings. Every task is graded by a program: coding answers

Fit: requants made for your cards

    

      Cuts a model from its full-precision source and picks each tensor's format for the cards
      this box actually has: the fastest format measured on the card is the base, and the VRAM the
      current model leaves spare is spent on the tensors that hurt most when squeezed (the output
      layer, attention values, FFN down, the first and last layers, the MTP draft head).
      Sizes are exact (llama-quantize's dry run); speeds come from your card's measurements.
      Quality is ranked by published sensitivity priors until KL divergence is measured
      (tabled), so every candidate is verified on the agentic and coding suites before you use it.
      Planning and building never touch a running server. Measuring, the importance matrix and
      verifying stop the instance they use and always start it again.

Recipes · read how a GGUF was made, make it again

    

      Explain compares a quantized file with its full-precision source and finds the
      llama-quantize command that reproduces every tensor's format: the stock mix it started from,
      the overrides on top (output layer, embeddings, MTP block, per-layer rules) and whether an
      importance matrix was used. A final dry run proves it tensor by tensor. Headers only:
      seconds, no GPU, nothing restarts. Build runs a recipe on a source here (CPU, low
      priority; the server keeps serving). Export gives a JSON file someone else can import
      to build the same layout; this box's paths are left out of it.
      An importance matrix changes which formats llama.cpp picks, not only the rounding, so a
      recipe made with one needs one to match. The maker's own is usually private: build or import
      one in card 4.

Refusals · uncensoring, phase 0

    
How often the running model refuses,
      scored the way Heretic scores abliteration: prompts aligned models usually refuse
      (mlabonne/harmful_behaviors) and ordinary ones (mlabonne/harmless_alpaca)
      to catch over-refusal, each reply's opening checked for refusal phrases. Downloaded on first
      use, not shipped. Nothing restarts: it sends one chat request at a time to the running
      server, so other clients wait a few seconds between them. Refused counts only a
      first-person refusal at the start of the reply ("I can't…", "I won't…", "Sorry…").
      Keyword is Heretic's own score, for comparison: it also counts an answer that opens
      with "this is illegal" and then complies, so it runs high. Check the listed verdicts.

4 · Importance matrix

    
Runs a high-precision copy of the
      model over calibration text and records which weights carry signal, so the quantizer rounds
      those more carefully (the i-quants gain most). One-time cost per model, reused by every
      build. GPU work: stops the instance for the collection (roughly 20-40 min on a Q8_0
      reference that spills a few layers to the CPU; ~10 min on today's model, less accurate).
      The Q8_0 reference is built first on the CPU (~15 min, ~29 GB disk).

5 · Parts and other engines

    
llama.cpp cannot load a projector from
      inside the model file; it always takes --mmproj separately, so Fit builds the
      projector as its own file (Q8_0 is ~2/3 the size of F16). stable-diffusion.cpp keeps the VAE at
      f16 by default: it is small and quantizing it shows as banding. audio.cpp takes per-prefix keep rules.

Power cap

    

    

    
A cap limits average board power (PPT). It lowers
      sustained draw and heat, but sub-second spikes still go through, so it is not a fix for
      transient trips. Applied caps are saved and re-applied by the panel at start and every minute,
      so they survive reboots and GPU resets. Clear forgets the saved cap; the live value
      stays until the next reboot.

GPU tuning

    
Every card in detail; its clocks, voltage, power cap
      and fan changed through the power helper (range-checked, read back, logged in Power options); and each change
      measured on this box's own workload. Changes here are live only: a reboot brings back the card's stock
      table unless a boot profile (Power options) says otherwise, so an unstable setting is undone by restarting the
      box. Apply and test runs the benchmark straight after the change and puts the previous values back if
      the run fails, the server dies, the driver resets the GPU or a thermal limit trips. LLM decode reads every
      weight for each token, so it is bound by memory bandwidth (fit/FINDINGS.md): memory
      clock tends to move tokens/s, core clock mostly moves watts. Measure it here before you believe it.

Crash analysis

    

      Reconstructed from the journal and the parameter history, not from the live
      process. Diagnostics only ever describes what is running now, so minutes
      after a hard lock it reports every check green — which is exactly what it did
      on the morning this was written. A host hard lock leaves no shutdown sequence in
      its boot, so the test used here is negative: a boot that ended with no
      poweroff/reboot markers and is followed by another boot died on its feet.

      Every save writes a backup, so file mtimes are a real changelog. This is what

Automatic updates

    

      Once a day at the time given (UTC), fetch the newest release of each chosen flavour,
      unpack it beside the existing builds and check that it runs. Hold then waits for you
      to press Activate; Auto also makes it the active build. Nothing ever restarts a running
      server: a new build is used the next time an instance on it starts, and every older build
      stays on disk for rollback unless you set how many to keep.

    

  

  

  
Installed llama.cpp builds

    

      Builds live side by side under ~/llama; each backend records which one
      it launches from in panel/builds.env. Nothing is overwritten in place,
      so rolling back is the same dropdown as upgrading. A build is classified by the
      ggml library it ships, not by its directory name.
      Changing the active build needs a restart to take effect.
    

    

    
  

  
Available upstream

    

      Recent releases from ggml-org/llama.cpp carrying an x64 Ubuntu asset
      this box can run. Downloads unpack to a staging directory and are only promoted
      once they yield a working llama-server of the expected flavour, so a
      dropped connection cannot leave a half-build selectable.
